# A System 573 cabinet on a USB_2_573 board

A Dance Dance Revolution, GuitarFreaks, DrumMania, Dance Maniax or Mambo a GoGo cabinet whose System 573 has made way for a PC: the [USB_2_573](https://github.com/Roganis/USB_2_573) board takes the 573's place on the cabinet's wiring and is on USB for HIRAKU (`--usb573`, `runtime/host/usb573.h`). The cabinet's switches reach the game as its JAMMA harness has them, and the game drives the cabinet's lights, its coin counters and, on a DDR cabinet, its stages. Nothing is bound and no lights file is written.

**Not yet checked on a board or a cabinet.** The firmware and this driver are tested against each other (`tests/usb573/`); the hardware is a design (the board's `docs/HARDWARE.md`).

## Setting it up

1. The board in the cabinet, in the 573's place (its own `docs/CABINETS.md`): the JAMMA harness, the lights' plugs, EXT-IN, EXT-OUT and ANALOG where the cabinet uses them.
2. The board's USB cable to the PC.
3. Linux only, once: a udev rule lets you open the board's raw interface. Then plug the board in again.

   ```bash
   printf '%s\n' \
     'KERNEL=="hidraw*", ATTRS{idVendor}=="1209", ATTRS{idProduct}=="0001", ATTRS{product}=="USB_2_573*", TAG+="uaccess"' \
     | sudo tee /etc/udev/rules.d/70-hiraku-usb573.rules >/dev/null
   sudo udevadm control --reload && sudo udevadm trigger --subsystem-match=hidraw
   ```

   On Windows there is nothing to install.
4. Start a System 573 game from the launcher. **Settings > Cabinet I/O > System 573 cabinet board** is "When it is plugged in" by default, so there is nothing to set. The game's log has lines starting `usb573`: `the cabinet's board is connected`.

| Setting | Option | What it does |
|---|---|---|
| When it is plugged in | `--usb573 present` | The board is used if it is there when the game starts. Without it the game starts as on any PC |
| Always | `--usb573 auto` | The board is looked for every second, also after the game has started, and after it was unplugged |
| Never | `--usb573 off` | The board is left alone: its gamepad interface is a plain controller then |

`--usb573 PATH` takes one board by its HID path. `--usb573-debounce US` changes how long the board leaves a switch alone after it changed (its own: 2000 microseconds; 0: none). `HK_USB573_LOG=1` prints the reports.

The keyboard and other controllers go on working beside the cabinet (Test on F2, a coin on 5). The board's lamps are off before a game starts and after it ends, and a second after HIRAKU stops talking to it (the board's own failsafe).

## What goes through

**In.** The 26 switches of the JAMMA edge and EXT-IN: both players' joystick directions, buttons 1 to 6 and Start, the two coin switches, Service and Test. They go to the bits of the 573's input registers they are wired to (`Core::wired_inputs`, `runtime/sys573/wiredpins.h`), so each game finds its controls where its cabinet has them: DrumMania's pads on player 1's joystick pins, a GuitarFreaks guitar's knob on two of them, DDR Solo's twelve sensors. The game's own I/O check in test mode shows them too. A switch that closes and opens again within one frame still counts for a frame. The ANALOG port's four channels go to the 573's ADC.

**Out.** Every change the game makes to the I/O board's 28 light outputs (the analog board's and the digital one's), to EXT-OUT's eight and to the two coin counters (`Core::wired_outputs`), in the order the game made them, a millisecond or so after the frame was emulated. No lamp table is in between: an output MAME has no name for is driven like any other.

The lamp names of [LIGHTS.md](LIGHTS.md), the lights file and the lights socket are apart from this and work as before.

## A DDR cabinet's stages

Each stage of a two-player DDR cabinet has a board (GN845-PWB(B)) between its panels' sensors and the JAMMA harness. After power-on it holds the right and up lines and gives the panels only once the game has spoken to it, bit by bit, over two of the I/O board's light outputs (A4 data and A5 clock for stage 1, B4 and B5 for stage 2).

The game speaks to the stage's board emulated in HIRAKU, as it always did, and gets its answers from it. The same edges go to the real board through the USB_2_573:
- one by one and in order, never merged, at the game's own pace kept between half a millisecond and two between edges;
- a stage's panels count as let go from the start until its board has had the last edge for a tenth of a second, and again whenever the game speaks to it (test mode's sensor check);
- a board plugged in after the game spoke gets the whole dialogue then.

This rests on the real board taking the game's dialogue at that pace without its answers being read. It is the first thing to check on a cabinet. A cabinet whose panels are wired straight to the JAMMA harness (no stage board, or a bypassed one) works the same way: the dialogue goes nowhere.

## The game menu

The [game menu](PLAY.md#the-game-menu-changing-games-from-the-cabinet) started for such a cabinet takes the board too: the cabinet's switches by the names of its controls (DDR's panels and Start, DrumMania's pads and Select, a guitar's neck and pick), so the cabinet chooses its games. Test and Service held together leave a game for the menu, as on any cabinet without a 10-key. The menu's lamps stay dark on the cabinet for now. On a DDR cabinet whose stages no game has spoken to since it was turned on, a stage that holds right and up is not read as panels: Start plays the game shown, and once a game has run the panels choose.

## Sound and picture

The board carries neither. The sound is the PC's own output into the cabinet's amplifier (the RCA plugs that went to the 573). The picture is the PC's video output: a 573 cabinet's monitor takes 15 kHz RGB with composite sync, which most PCs' outputs don't make by themselves.

## For developers

- `runtime/shell/wired573.h`: the switches' and outputs' bits, the board's own numbering. `Core::wired_attach`, `wired_inputs`, `wired_outputs` (`runtime/shell/core.h`); the 573 core's are in `runtime/sys573/board.cpp` (`set_pins`, the registers' reads).
- `runtime/sys573/wiredpins.h`: which pin each bit of the I/O boards' registers drives. `tests/usb573` checks MAME's lamp numbers against the cabinets' wiring through it.
- `runtime/host/usb573.cpp`: the board's thread (a report read each millisecond, output entries sent as the board has room, a keepalive every 200 ms), the stages' rules, the game menu's names. `usb573_hid.cpp`: SDL's hidapi.
- The protocol is the board's (`docs/PROTOCOL.md` there). `tests/usb573/firmware/` is a copy of its firmware's core, which the test runs as the pretend board: copy it again when the protocol changes.
